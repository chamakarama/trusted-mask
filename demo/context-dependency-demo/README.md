# Context-dependency demo: same notes, different task

Use this fictional 80-word message: the user adds a brief introduction and their manager's work-from-home agreement, then pastes the GP's appointment summary. A return-to-work email is a credible reason to paste it, and the medication summary gives a clear second purpose. The source text stays identical throughout.

## Record the demo

1. Load [message.txt](message.txt) into the data/message panel.
2. Set the separate intended-use field to [manager-task.txt](manager-task.txt):

   > Write an email to my manager requesting temporary desk duties. Include my return date, restrictions and work-from-home days.

   Preview the result. The name becomes `[PERSON_1]`. The return date, lifting/standing restrictions, review date and work-from-home days remain. The operation detail and entire psychiatric-history paragraph are removed.
3. Change **only the intended-use field** to [clinician-task.txt](clinician-task.txt):

   > Summarise my health, medication and recent symptoms for my new GP.

   Preview again. The name is still `[PERSON_1]`, while the medical history, medication, dose, sleep report and absence of recent dose changes all remain.
4. Optionally switch back to the manager task to show the same result returning.

Narration: **“I pasted the same clinic note twice. For a work email, Mask keeps the adjustments I need. For a GP summary, it keeps the medical details. My name stays private in both.”**

Show the protected input to the cloud AI. These are privacy-transformation outputs, not an email or medical summary generated by a downstream AI.

## Runtime and verification

Verified on 8 November 2026 with the downloaded **DeBERTa-v3 Base epoch 2** bundle (`deberta-v3-base-section-v1`) and the complete local Python pipeline. The app preview passed all 16 content/status checks over manager → clinician → manager, and switching back reproduced the first output exactly. Model weights, policy thresholds and UI defaults were unchanged.

Use the new model with its section-removal pipeline and supply the intended task separately. This check did not exercise the deployed browser or send a provider request; a browser using the old model/export will not necessarily reproduce these outputs.

The example is synthetic and selected for presentation after testing four note formats with two task pairs. Two further introductions were tested for this wording revision; all four resulting outputs are in [revision-2/candidate-results.json](../../evidence/privacy-v1/context-demo-20261108/revision-2/candidate-results.json).
