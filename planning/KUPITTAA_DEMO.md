# Since AI at Kupittaa — synthetic demonstration

Frozen before generation/publication, 7 November 2026. This is an invented stress-test scenario, not actual Since AI attendance, dates, boarding records or a service recommendation.

- Target: the public area containing Föli's Kupittaan asema stop (22.29464348, 60.45090356), TRK-G14. This is a public reference point, not a claimed hackathon venue.
- Population: 2,000 fictional background cards plus 10,000 fictional attendee cards, seed 2026110701. The deliberately exaggerated attendee count makes the privacy/utility tradeoff visible; it is not an attendance estimate.
- Event: morning inbound journeys and afternoon returns on two invented weekdays, 30–31 October 2025, within the adapter's fixed illustrative calendar. Background journeys use the remaining public zones throughout weekdays. Every card uses a new HACK- identifier namespace; none represents a person/card in the earlier synthetic population.
- One release, `kupittaa-hackathon-v1`, epsilon 1 under the unchanged card-level mechanism/caps. Independent fictional population, dedicated explicitly scoped ledger; no overlapping baseline publication or per-person difference query. This does not authorise resetting budgets for overlapping real populations.
- Validate once: Kupittaa ranks first in morning protected destination demand; its morning hourly demand exceeds midday; compare raw inferred and protected area totals and retain all error/uncertainty results, successful or not. No noise redraw or seed change to improve the picture.
- The map reads the exact protected artifact; a downloaded portable JSON embeds the same nine verified files. Its convenience aggregate table is derived only from signed released cells, summed before clamping.
- Public Föli route geometry and stops are separate public reference data. Route demand is a shortest-path assignment, not measured bus occupancy, identified passenger paths, or capacity need.

Demo: upload raw ZIP → validate/review/protect → inspect utility → download protected JSON → open the same file in the planner → inspect Kupittaa inbound routes → upload only that file manually into a fresh ChatGPT conversation → ask about a fictional commuter and then aggregate destination demand. Do not script or fabricate ChatGPT's response; inability to retrieve a person illustrates the boundary, not a proof of privacy.
